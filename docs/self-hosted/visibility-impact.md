## Decision and execution sequence (future approved task)

1. Keep current visibility until owner approves policy and plan/access matrix. Treat previously public source as permanently disclosed; legal ownership and technical confidentiality are distinct.
2. Prepare an isolated private rehearsal repository (requires separate user authorization before creation/settings changes), with synthetic data and no production deploy secrets. Test CI/checks, review apps, package auth, artifacts and billing visibility there.
3. Agree independent app build/publish/rollout approvals. Do not use public-to-private change as a substitute for release authorization or automatically move deploy credentials to bypass plan limitations.
4. At approved change time, pause new release actions through an approved procedure, verify no deployment in flight, switch visibility, revalidate rules/apps/checks and non-deploy fetch/build. No DNS/container restart required solely for visibility.
5. If access/guards fail, stop releases and fix grants/plan; **do not automatically make repo public again**, which may expose new private changes. Running stores remain local and independent.
