Panduan Git Clone & Toko Mandiri

Pendaftaran hanya mencatat informasi toko. Tidak ada akun pusat, pairing VPS, atau instalasi jarak jauh. Admin dan data toko dikelola pada server milikmu sendiri.

1. Siapkan lingkungan

Profil produksi aplikasi memerlukan Ubuntu 22.04/24.04 amd64, minimal 2 vCPU, RAM 4 GiB dan ruang kosong SSD 40 GiB. Siapkan domain, Docker Engine dengan Compose, PostgreSQL privat, volume media persisten, serta backup. Shared hosting PHP belum tentu kompatibel. Jangan memakai server toko aktif untuk percobaan instalasi baru.

2. Unduh source code resmi

Gunakan clone dangkal agar tidak mengunduh riwayat pengembangan. Repository ini berlisensi Apache-2.0; pemberitahuan komponen pihak ketiga tetap berlaku.

git clone --depth 1 https://github.com/Assyauq26/Gheverhan.git
cd Gheverhan
git rev-parse HEAD

Buka Repository GitHub · Lihat Releases

Catat SHA yang diunduh. Jangan menyalin direktori data PostgreSQL, backup, media pelanggan, file .env, atau kredensial Gheverhan. Jangan menjalankan seed demo sebagai data toko produksi.

3. Periksa dukungan instalasi sebelum menjalankan

Belum tersedia installer Git Clone mandiri satu perintah.

Source memiliki konfigurasi Docker dan admin lokal, tetapi bootstrap lama menggunakan pairing pusat. Alur itu tidak dipakai pada konsep pendaftaran baru. Skrip fixture bukan installer produksi. Jangan menjalankan perintah install.sh yang tidak tersedia atau menyetel mode pengujian untuk melewati keamanan.

Administrator server perlu meninjau kontrak konfigurasi self-hosted dan menyiapkan instalasi lokal yang diverifikasi sebelum menerima pelanggan. Clone saja belum menghasilkan toko online. Bila membutuhkan pemasangan siap pakai, tunggu panduan instalasi lokal yang telah diuji; jangan masukkan data pelanggan pada instalasi percobaan.

Komponen yang tersedia untuk ditinjau:

  • deploy/self-hosted/Dockerfile: target build aplikasi dan migrasi terpisah.
  • deploy/self-hosted/compose.yml: database privat, media persisten, aplikasi dan Caddy. Konfigurasi rahasia serta identitas instalasi harus unik.
  • frontend/scripts/self-hosted-issue-admin.ts: penerbitan klaim admin lokal ke file privat pada server toko yang sudah dikonfigurasi. Token tidak boleh dibagikan.

Identitas brand dan admin dibuat pada aplikasi lokal, bukan pada formulir pendaftaran. Jangan menggunakan database, session, atau password toko demo.

4. Kelola toko setelah instalasi terverifikasi

Buka storefront dan dashboard lokal. Atur nama brand, logo, kategori, produk, harga, stok, foto, dan Dekorasi Toko. Pastikan HTTPS valid, media serta database tetap ada setelah restart, lalu uji backup dan restore. Checkout dan J&T produksi memerlukan validasi serta otorisasi tersendiri; pendaftaran ini tidak mengaktifkannya.

Pembaruan dan pemulihan

Tinjau release dan perubahan migrasi sebelum memperbarui source. Buat backup database/media, uji versi baru pada lingkungan terpisah, dan siapkan rollback yang tidak menghapus data. Tidak ada agent update atau pemantauan VPS dari platform pusat.
