## Frontend-to-backend handoff (design only)
RegistrationDraft: ownerName, normalizedEmail, phone, brandName, category?, slug, consent; only component/DOM lifetime. Password and confirmation remain input values, never persist in a saved draft.
StartRegistrationRequest: reviewed account/store fields + password + versioned consent; future server validates normalization, password, availability, anti-abuse and atomic uniqueness.
VerifyOtpRequest: challengeId + six-digit code; future server enforces TTL, attempts, replay rejection and resend policy.
ProvisionStatus: state + safe progress/errorCode; URLs only after real tenant/domain/TLS readiness. Proposed states pending_verification, queued, provisioning, ready, retryable_error; these are not runtime APIs.
No endpoints or transports are wired. A future secure same-origin API/CORS-CSRF/auth contract and server implementation require a separate PR after UI approval.
